# Deploying Argus

Free tier throughout: Render for the app, Neon for Postgres, CloudAMQP for the
broker. No card required for any of them.

---

## 1. Connect Render to the repository

1. Sign in at [render.com](https://render.com) with GitHub
2. **New → Blueprint**
3. Select `zakaullah075/argus-siem`
4. Render reads [`render.yaml`](render.yaml) and offers to create the service
5. It will prompt for the values marked `sync: false` — that is step 2

The blueprint sets everything that is not a secret: health check path, JVM
flags, connection pool sizing, TLS for the broker, and a generated JWT secret.

## 2. Environment variables

Enter these in Render's dashboard. **Never commit them.**

| Variable | Where it comes from |
|---|---|
| `SPRING_DATASOURCE_URL` | Neon, converted to JDBC form (see below) |
| `SPRING_DATASOURCE_USERNAME` | Neon connection string, user part |
| `SPRING_DATASOURCE_PASSWORD` | Neon connection string, password part |
| `SPRING_RABBITMQ_HOST` | CloudAMQP host, e.g. `capybara.lmq.cloudamqp.com` |
| `SPRING_RABBITMQ_USERNAME` | CloudAMQP user |
| `SPRING_RABBITMQ_PASSWORD` | CloudAMQP password |
| `SPRING_RABBITMQ_VIRTUAL_HOST` | Same as the CloudAMQP user |

`ARGUS_JWT_SECRET` is generated by Render — do not set it by hand, and do not
reuse the development default. Anyone holding it can mint a token for any tenant.

### Converting the Neon URL

Neon gives a libpq URL. Spring needs JDBC, and the credentials must be separate:

```
neon:  postgresql://USER:PASSWORD@HOST/DATABASE?sslmode=require
       ↓
url:   jdbc:postgresql://HOST/DATABASE?sslmode=require
user:  USER
pass:  PASSWORD
```

The `jdbc:` prefix matters, and leaving credentials embedded in the URL while
also setting username and password causes confusing authentication failures.

### CloudAMQP

Port **5671**, not 5672 — hosted brokers require TLS. `SPRING_RABBITMQ_SSL_ENABLED`
is already `true` in the blueprint. The virtual host equals the username; shared
brokers isolate accounts that way, and omitting it produces an access-refused
error that reads like a wrong password.

## 3. Deploy

Render builds the Dockerfile and starts the service. First build takes several
minutes; Maven has to download dependencies inside the build container.

Flyway creates the schema on first boot. Nothing to run by hand.

## 4. Verify

```bash
curl https://<your-service>.onrender.com/actuator/health
# {"status":"UP"}
```

Then seed a tenant and an admin. There is no bootstrap endpoint yet, so use
Neon's SQL editor:

```sql
insert into tenant (id, name, plan, rate_limit_per_minute)
values ('11111111-1111-1111-1111-111111111111', 'Demo', 'free', 600);

-- bcrypt hash of 'demo-password-change-me'
insert into app_user (tenant_id, email, password_hash, role)
values ('11111111-1111-1111-1111-111111111111',
        'admin@demo.test',
        '$2a$10$N9qo8uLOickgx2ZMRZoMyeIjZAgcfl7p92ldGxad68LJZdL17lhWy',
        'ADMIN');
```

Change that password before showing the demo to anyone.

## 5. Keep it awake

Render's free tier stops the service after 15 minutes idle, and a cold JVM takes
roughly a minute to respond. A recruiter opening the link in that window sees a
dead page.

[`.github/workflows/keep-warm.yml`](.github/workflows/keep-warm.yml) pings health
every 10 minutes. Enable it by setting a repository variable:

**Settings → Secrets and variables → Actions → Variables → New**
`ARGUS_URL` = `https://<your-service>.onrender.com`

Without that variable the workflow exits quietly rather than failing.

## Free tier limits

| | Limit | Consequence |
|---|---|---|
| Render | 512 MB RAM | Tight for Spring Boot + JPA + AMQP. `MaxRAMPercentage=70` and `SerialGC` are what make it fit. |
| Render | Sleeps at 15 min | Handled by the keep-warm workflow |
| Neon | 0.5 GB storage | Thousands of events, fine for a demo |
| Neon | Connection cap | Pool capped at 5 |
| CloudAMQP | 1M messages/month | ~30k events/day |

If the container runs out of memory, the options in order are: drop
`DB_POOL_MAX` to 3, remove the management endpoints, or move to Oracle Cloud's
always-free VM (24 GB, but identity verification and a less reliable signup).

## Rotating credentials

Both providers rotate in two clicks — Neon under **Roles**, CloudAMQP by
recreating the instance. Update the values in Render and redeploy. Worth doing
whenever a connection string has been pasted anywhere it shouldn't have been.
